# 案例一：老带新增长

## 业务背景

二季度业务希望扩大日活规模；外部可投放拉新流量承压，增长团队推出老带新活动，通过老用户邀请带来新用户。本人在导师指导下参与指标体系、看板监控、异常定位、页面实验和首月价值评估。

项目的最终业务结果是拉新用户数，页面策略直接作用的核心机制指标是邀请点击率。

## 指标链路

```text
活动页面曝光 UV
→ 页面访问 / 点击
→ 老用户点击邀请
→ 成功转发到微信
→ 新用户访问
→ 新用户激活
→ 新用户质量与首月价值
```

指标角色：

| 角色 | 指标 | 用途 |
|---|---|---|
| 最终结果 | 老带新拉新用户数 | 判断是否扩大有效新增 |
| 核心机制 | 邀请点击率 | 判断页面是否促成邀请动作 |
| 诊断指标 | 分享成功率、各节点转化率 | 判断损失发生在哪一段 |
| 质量护栏 | 新用户回访和活跃 | 防止只增加低质量用户 |
| 决策护栏 | 首月价值/激励成本倍数 | 判断投入效率是否可接受 |

## 第一次策略迭代与异常

活动初期记录的投入效率指标约为 2.90。该阶段的公开复盘未完整披露价值窗口和成本范围，因此不将 2.90 与后续首月价值/激励成本倍数 2.18 作同口径趋势比较。在以扩大用户规模为目标的背景下，团队增加激励强度并加入留存成功玩法。

版本上线后：

- 邀请点击率由约 21% 下降到 17%；
- 分享成功率仍约为 95%。

分享成功率约 95% 属于反向证据：它降低了“用户点击邀请以后无法完成分享”作为主要解释的优先级，但不能证明分享链路绝对没有问题。

结合产品和用户研究反馈，形成待验证机制假设：

- 新页面介绍内容增加，信息焦点分散；
- 邀请按钮被放到第二页；
- 产品与用户研究反馈显示，部分老用户难以在第一时间识别核心动作，并选择退出。

在实验前，这些只能叫产品机制假设，不能直接写成已经证明的根因。

## 页面改版与实验

实验策略：

- 实验组：简化活动首页，将邀请按钮放在第一页明显位置；
- 对照组：保留旧版页面；
- 核心指标：邀请点击率；
- 最终业务指标：拉新用户数；
- 护栏：新用户质量与首月价值/激励成本倍数；
- 周期：两周；
- 总样本：约 700 万；
- 结果：17%→23.5%，`p<0.05`。

效果量：

```text
绝对提升 = 23.5% - 17.0% = 6.5 个百分点
相对提升 = (23.5% - 17.0%) / 17.0% = 0.065 / 0.17 ≈ 38.2%
```

实验支持的是“完整页面简化方案”提高邀请点击率。如果同时改变信息量、页面层级和按钮位置，不能把全部效果单独归因于按钮前置。

## 实验可信度流程

该作品将项目参数与可复用实验检查清单分开：

1. 明确策略目标和最接近策略的核心指标；
2. 设定基线 17%、MDE +3pp、`α=0.05`、Power 80%；
3. 计算最低样本量并覆盖完整业务周期；
4. 按用户 ID 稳定 Hash 分流，1:1 分组；
5. 按 SOP 检查 A/A、SRM、埋点和画像均衡；本项目复盘未披露这些检查的实际结果，页面不默认标记为通过；
6. 实验中监控护栏，不因短期 P 值显著提前停止；
7. 实验结束同时检查统计显著、业务显著和护栏。

页面会明确标识哪些是项目公开事实，哪些是方法论沉淀，避免将通用检查清单混同为项目中已经执行且通过的内部流程。

## 首月价值决策

项目采用：

```text
首月新用户价值
= 月活跃天数 × 日活跃时长 × 单位时长商业化价值

首月价值/激励成本倍数
= 首月新用户价值 / 归因激励成本
```

策略版本结果为 2.18，同口径外部投放基准为 1.90，因此在相同价值窗口、成本范围和归因规则下，支持在该版本上持续迭代和优化。

边界：

- 2.18 不是完整生命周期 LTV；
- 不是净利润率；
- 不是标准财务 ROI；
- 如果外部渠道使用不同观察窗口或成本范围，则 2.18 和 1.90 不能直接比较。
