# 数据卡

## 数据用途

数据用于复现用户增长分析方法、驱动前后端和自动化测试。它不用于估计相关公司的整体表现，也不代表任何雇主生产数据库。

## 四类信息必须分开

| 类型 | 定义 | 示例 |
|---|---|---|
| 项目事实 | 来自个人实习复盘、允许公开的指标变化和项目过程 | 邀请点击率 17%→23.5%；次 7 日内留存 48%→41% |
| 演示数据 | 固定规则生成的行级记录、分群占比和时间序列 | 某演示周的渠道构成、每日趋势、样例用户 |
| 程序复算 | 由事实或演示数据计算的派生结果 | +6.5pp、约 +38.2%、样本量试算、模拟数据的结构贡献 |
| 方法论沉淀 | 项目后整理的通用检查清单 | SRM、A/A、网络效应与三类决策条件 |

页面与 API 使用 `source_type` 和 `synthetic` 字段标识这些类型。

## 允许公开的案例事实

### 老带新增长

- 邀请点击率在策略版本变化后约 21%→17%；
- 分享成功率约 95%；
- 页面简化实验对照组 17%、实验组 23.5%；
- 绝对提升 6.5 个百分点，相对提升约 38.2%；
- 实验周期两周、总样本约 700 万，`p<0.05`；
- 项目口径的首月价值/激励成本倍数 2.18；
- 同口径外部投放基准 1.90。

首月价值/激励成本倍数不是完整生命周期 ROI、LTV/CAC 或净利润率。激励调整在公开演示中只使用指数或方向性表达，不展示内部金额明细。

### 新用户留存

- 次 7 日内留存率 48%→41%；
- 观察中平板留存较手机低约 10 个百分点；
- 标杆用户关注渗透约为非标杆的 2.5 倍；
- 产品核心路径转化未见明显同步下滑；
- 引导策略实验周期两周、总样本约 30 万，`p<0.05`。

项目复盘未披露实验组和对照组的绝对留存率，因此：

- 不展示绝对提升；
- 不计算相对提升；
- 不声称独立验证了业务显著性；
- 只保留统计显著和项目继续推进的事实边界。

## 次 7 日内留存定义

分母：某日首次进入产品的新用户数。

分子：这些用户在首次进入后的第 1—7 天内至少再次访问一次的人数。

这不是“第 7 日当天留存率”，也不与 D7 retention 混用。

## 设备结构贡献

精确结构贡献至少需要：

- 设备占比的前后变化；
- 各设备分层留存的前后变化；
- 一致的新用户口径和观察窗口。

仅知道“平板比手机低约 10pp”不能推出结构贡献。演示数据可以计算一个示例贡献，但必须标记为 synthetic，不得称为实习项目真实贡献。

## 生成与复现

演示数据使用固定随机种子生成，包括：

- 用户与获客上下文；
- 活动版本和邀请事件；
- 新用户日级活动；
- 产品行为；
- 实验分组与曝光；
- 首月价值和归因激励成本；
- 数据质量和指标快照。

相同代码、种子和参数应产生相同结果。公开分析包保存生成版本和时间。

## 不包含

- 真实用户标识或行为明细；
- 内部组织层级、表名、事件名或系统地址；
- 公司后台截图、生产 SQL 或生产代码；
- 账号、API Key、Cookie、Token 或凭证；
- 原始简历、联系方式或面试材料；
- 未经确认的实验效果量；
- 被包装成真实事实的模拟用户结构。

## 已知限制

- 演示数据用于验证分析链路，不支持外推公司整体经营结果；
- 老带新的最终新增用户增量未在公开事实中给出；
- 新用户留存实验缺少绝对效果量和完整护栏结果；
- 可选叙事模型只改善表达，不改变确定性计算。
